## Changes Summary

### Source Code Changes

**File:** `src/discovery/lifecycle.mjs`

**Change:** Extended permanent-error classification to include HTTP 502 (backend unreachable) alongside 404/410.

**No Changes To:**
- AC3 (Ornith purge): Completed externally by Lumina
- AC4 (honest capacity): Evidence and documentation only; no source code changes needed

```diff
-  if (status === 404 || status === 410) {
+  if (status === 404 || status === 410 || status === 502) {
     const consecutive_permanent_errors = lc.consecutive_permanent_errors + 1;
     if (consecutive_permanent_errors >= thresholds.eolErrorThreshold) {
       return {
         ...lc,
         state: LIFECYCLE_STATES.EOL,
         consecutive_permanent_errors,
         consecutive_successes: 0,
-        eol_reason: 'provider_410',
+        eol_reason: status === 502 ? 'backend_unreachable' : 'provider_410',
         eol_at: now,
       };
     }
     return { ...lc, consecutive_permanent_errors, consecutive_successes: 0 };
   }
```

**Impact:** Models with unreachable backends (connection-refused, absent-listener) will now be classified as EOL after 3 consecutive 502 errors, rather than remaining in the catalog indefinitely.

## Limitations and Known Issues

### Fast-Failure Classification

1. **502 is broad:** Covers connection-refused, absent-listener, and general network errors. All are treated identically.

2. **No periodic sweep:** This repair only classifies fast failures on actual completion requests. It does NOT add a periodic catalog liveness sweep (noted in Lumina's skmail but not in original card ACs).

3. **Threshold unchanged:** The `eolErrorThreshold` (default 3) applies to both 404/410 and 502. If different thresholds are needed, a new constant would be required.

### Honest Physical Capacity

1. **No bucket-to-capacity-domain mapping:** Bucket resolution doesn't expose which members share capacity domains. This is documented in AC4 evidence.

2. **No `/admin/bucket` endpoint:** No operator endpoint to query bucket membership with capacity domain context. Operators must cross-reference `/queue`.

3. **Manual correlation required:** To verify honest capacity, manually map bucket members to `/queue` capacity domains.
